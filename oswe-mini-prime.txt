## Root-Cause Analysis & Evidence (summary)
- Problem 1 — Overlapping header + content (mid-sized viewports, e.g., 13" laptops):  
  Root cause: header had position: sticky/top, but content did not account for header height at some breakpoints, so content could appear under the header at certain viewport sizes.  
  Fix: Add padding-top to `.content` equal to header height. Adjust header height and responsive rules for smaller screens. Evidence: Playwright layout traces (`docs/screenshots/layout_trace_desktop.json` and `layout_trace_laptop13.json`) comparing headerRect.bottom vs contentRect.top.
- Problem 2 — Primary Submit CTA hidden by sticky footer in mobile Safari:  
  Root cause: iOS Safari can overlay content with the bottom safe-area or a sticky footer; CTA anchored in footer was covered.  
  Fix: Use `env(safe-area-inset-bottom)` in `padding-bottom` and provide a CTA inside content (floating/sticky above the footer) while accounting for the safe area. Evidence: Playwright layout traces for mobile Safari, screenshots (`docs/screenshots/mobile_safari_cta.png`), and the test that ensures button visibility/clickability using `webkit` (Safari)
- Problem 3 — Markdown shows as raw HTML in dark mode or theme inconsistent:  
  Root cause: The Markdown renderer wasn’t configured to accept safe HTML and then sanitize it, so markup or raw HTML could appear invalid or unstyled with different theme switches.  
  Fix: Use `react-markdown` with `rehype-raw` + `rehype-sanitize` to render allowed sanitized HTML and reuse CSS vars for theme styling. Evidence: Playwright dark-mode tests assert there is no raw '<div' in markup and checks computed styles in dark mode.
- Accessibility root-cause: Missing focus setting/keyboard support.  
  Fix: Add ref focusing on mount for inputs & main CTA. Provide ARIA and role attributes for steps and regions. Accessibility snapshots are generated as a part of tests (e.g., `docs/screenshots/a11y_snapshot_desktop.json`).
