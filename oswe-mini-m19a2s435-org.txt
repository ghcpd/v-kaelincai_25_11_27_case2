## 🧭 UI Flow & Root Cause Map (Load → Render → Interact → Submit)
- Load: Vite loads the app; `Wizard` imports local `mocks/mock_api.json` for `profile` and `handbook`.
- Render: `header` is sticky (top) and `footer` is sticky (bottom); main content uses grid layout (sidebar + panel).
- Interact: Step buttons (nav) and `Next/Submit` Primary CTA (footer) change the step. Keyboard navigation uses Arrow keys.
- Submit: Last step changes CTA to `Submit`; logs a structured event.

Root-cause evidence:
- Header overlapped the main grid due to missing/incorrect top padding for `main` on mid-size breakpoints (13" laptop).
- Primary `Submit` CTA was sometimes hidden/covered by sticky footer on mobile Safari due to lack of safe-area support and insufficient padding/CTA anchoring.
- Markdown misrendered or showed raw HTML in dark mode — previously the content contained inline tags since Markdown renderer wasn’t sanitized and CSS theme wasn’t specific for `.handbook`.

Fixes I implemented:
- CSS variables `--header-height` & `--footer-height` are defined and used to calculate `main` padding; updated for mid-size breakpoints (13”).
- For sticky footers & mobile Safari:
  - Use `env(safe-area-inset-bottom)` and body bottom padding to avoid covering content.
  - Add `.cta-anchored` CSS so CTA is positioned above the footer when needed.
  - Add small panel `padding-bottom` on small screens to keep content above footer.
- Markdown sanitization:
  - Implemented `react-markdown` with `rehype-sanitize` to prevent script tags or raw HTML injection from rendering.
  - Extended dark-mode styles for markdown to ensure consistent typography and color contrast.
- Accessibility updates:
  - Added `role`, `aria-live` for content updates, `aria-current` for step buttons, keyboard navigation (ArrowLeft/ArrowRight), `tabIndex` focus management, and structured UI logging with `sessionId`/`requestId`.
